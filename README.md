# Bug Radar

Дашборд для еженедельного разбора клиентских инцидентов из Jira.
Без бэкенда и без сборки: открыл файл, загрузил выгрузку — считает в браузере.

Проектная спецификация целиком — в [DESIGN.md](DESIGN.md). Этот README описывает
то, что уже работает (этап 1, MVP).

## Запуск

```bash
open index.html
```

Работает прямо из файловой системы (`file://`). Если удобнее по http:

```bash
npm run serve
```

Демо-данные, чтобы посмотреть интерфейс до подключения своей Jira:
`sample/incidents.csv` — 179 инцидентов за 10 недель, `sample/jira-ru.xlsx` — короткая
выгрузка с русскими заголовками Jira (Код, Тема, Создали, Дата завершения, Время восстановления).

## Загрузка данных

В Jira: поиск по JQL → Export → **Export CSV (current fields)** или **Export Excel**.
Подойдут CSV, XLSX и XLS: таблицу разбирает SheetJS (`js/vendor`, Apache-2.0), подгружается
лениво — только когда выбран не-CSV, дальше файл идёт по тому же конвейеру, что CSV; из
нескольких листов берётся самый заполненный. Файл перетащите
в окно загрузки, выберите кнопкой или вставьте текстом.

- **Русская выгрузка Jira узнаётся сама**: `Код`, `Тема`, `Метки`, `Ранг`, `Создали`,
  `Дата завершения` (это дата закрытия), `Время восстановления` (это дата исправления —
  момент, когда блокер снят у клиента). Даты приходят в двух видах — `Создали` как
  `2026-08-13 11:20`, `Дата завершения` как `11.08.2026 13:37` — оба понимаются, день в
  точечной записи идёт первым.
- **«Время восстановления» может быть длительностью**, а не датой: `2 ч 15 мин`, `1d 4h 30m`,
  `3 дн`, `02:15` — тогда дата исправления считается от даты создания. Голое число
  не трогаем: единицу измерения угадывать нельзя.
- **Статус закрытия — строго по слову**: «Готово» закрыто, «Готово к проектированию» — нет.
  «Проектирование», «Заблокирован», «Ready for Prod» — в работе; «Ожидает разработки» — новое.
  Если задача закрыта, а даты закрытия в выгрузке нет, берётся дата исправления, потом
  «Обновлено», и это помечается значком ≈ в таблице.
- **Дата раньше создания** (бывает при ручных правках в Jira): инцидент считается
  разобранным или закрытым — это факт статуса, — но в метрики времени отрицательный
  интервал не попадает. Предпросмотр импорта показывает, сколько таких строк.
- **Колонки распознаются автоматически** по заголовкам (`Issue key`, `Summary`, `Created`,
  `Resolved`, `Custom field (Дата исправления)`, `Custom field (Ранг)` — русские заголовки тоже).
  Если поля называются иначе, поправьте селектами: раскладка запомнится по именам колонок
  и переживёт смену их порядка в следующей выгрузке.
- **Повторная заливка обновляет, а не задваивает** — выгрузку можно перезаливать хоть каждый день.
- **Импорт ничего не удаляет.** Если инцидент убрали из фильтра в Jira, здесь он останется,
  и сообщение об импорте скажет, каких номеров не было в файле.
- Понимает форматы дат Jira (`13/Aug/26 3:04 PM`), локализованный (`13.08.2026 15:04`) и ISO,
  разделитель `;`, BOM, кавычки и переводы строк внутри ячейки.

Прямого обращения к Jira API нет намеренно: Jira Cloud не отдаёт CORS-заголовки для
авторизованных запросов, а API-токен в `localStorage` статической страницы — это токен
с полными правами учётки в открытом виде. Живая синхронизация — этап 2, через тонкий прокси,
который держит токен у себя (см. DESIGN.md).

## Что считает

**Решённым считается снятие блокера у клиента**, а не закрытие задачи в Jira:
момент разблокировки — самая ранняя из даты исправления и даты закрытия. Поэтому
инцидент с проставленной датой исправления уходит из «открытых», даже если тикет ещё висит,
а закрытие без даты исправления не наказывает команду за незаполненное поле.

| Метрика | Как считается |
|---|---|
| Пришло | создано внутри периода |
| Разобрано | блокер снят внутри периода |
| Закрыто | `resolutiondate` внутри периода |
| Исправлено, не закрыто | дата исправления в периоде, задача открыта |
| Открыто на конец | создано до конца периода и не разблокировано на эту дату |
| Просрочено по SLA | открыт дольше, чем SLA его ранговой полосы |
| Висят дольше X дней | открыт дольше настраиваемого порога |
| До взятия в работу | медиана и p85 по начатым в периоде |
| До исправления | медиана и p85 по разобранным в периоде |

Два правила, из-за которых числа отличаются от наивных:

- **Время жизни считается только по завершённым.** Возраст открытых — отдельная метрика,
  рядом, но никогда не в одной сумме: иначе чем дольше живёт инцидент, тем меньше шансов,
  что он попал в среднее, и метрика систематически занижена.
- **«Открыто на конец» считается на дату, а не на сейчас.** Прошлая неделя показывает то,
  что было тогда. Поэтому выборка тянется по всей истории, а не только по периоду.

Медиана — главное число, p85 — рядом: у времени жизни всегда тяжёлый хвост, и один
инцидент, провисевший три месяца, поднимает среднее так, что метрика перестаёт реагировать
на реальные изменения.

## Период

Неделя, две недели, месяц или произвольный диапазон. Стрелки сдвигают окно на его же длину,
по умолчанию открывается прошедшая неделя. Всё сравнивается с предыдущим периодом такой же
длины (для месяца — с предыдущим календарным месяцем).

Дельта красится по смыслу, а не по знаку: рост притока — плохо, рост разбора — хорошо.
Изменение меньше 5% и меньше двух штук показывается серым как шум — иначе «+1» красным
на недельных числах научит команду игнорировать цвета.

График потока — отдельный блок во всю ширину: 8 последних периодов того же вида, приток
и разбор парными столбиками от общей базы (сравнивать высоты из одной точки проще, чем длины
вверх и вниз от нуля), очередь на конец периода — линией по правой шкале. Значения подписаны
над столбиками и над точками, выбранный период подсвечен полосой. Клик по периоду открывает
его.

**Назад.** Каждый переход — клик по периоду на графике, drill-down из карточки, смена
вкладки — кладётся в историю браузера. Вернуться можно кнопкой «‹» в шапке, клавишей
`Backspace` или системной кнопкой «назад».

## Ранг

Ранг — настраиваемое и необязательное измерение.

- Порог переключается прямо в шапке: `≥30 · ≥50 · ≥70 · все`.
- Для инцидентов **без ранга** есть режим: не учитывать (по умолчанию), учитывать,
  либо только их — чтобы открыть список неоценённых и проставить ранги.
- Счётчик «без ранга: N» стоит рядом с фильтром всегда и кликабелен: тихо терять часть
  выборки нельзя.
- **Ранга может не быть вовсе.** Выключите его в настройках — полосы схлопнутся, SLA
  возьмётся единый, всё остальное продолжит работать. Ни одна метрика ранга не требует.
- Границы полос и SLA по каждой полосе редактируются в настройках; цвет строки в таблице —
  следствие этих порогов, а не оформление.

Ранг фильтруется по текущему значению. Исторический ранг на дату — этап 4.

## Экраны

**Обзор.** Карточки метрик, график потока, открытые по рангу, воронка когорты
(что стало с пришедшим за период) и блок **«Требуют обсуждения»** — повестка встречи,
собранная автоматически: просроченные, без исполнителя, без движения. Сортировка по
«стоимости» ранг × возраст.

**Инциденты.** Таблица с сортировкой по любой колонке, поиском и фильтрами, экспортом в CSV.
Красная полоса слева — просрочен, янтарная — на грани, серый текст — уже разобран.

Любое число на обзоре кликабельно и открывает таблицу с этим списком: KPI-карточка,
полоса ранга, счётчик без ранга.

## Настройки

Адрес Jira для ссылок на задачи (номера в таблице станут ссылками), ранг и его полосы,
SLA в часах по каждой полосе, пороги «висит дольше» и «без движения», тема.

Дизайн-система — та же, что в `sprint-progress`: чёрный фон, индиго-акцент, тонкие границы,
Inter. Каркас тоже общий: боковая панель с навигацией и блоком «Данные», топбар с заголовком
и мета-строкой, hero-блок, сетка метрик, карточки. Одна тёмная тема.

Кнопка «Удалить все данные» очищает состояние; автосохранение и бэкап — в боковой панели
(см. «Сохранение данных»).

## Сохранение данных

Состояние живёт в `localStorage` этого браузера. Этого достаточно, пока вы работаете
с одной машины и не чистите кеш, — поэтому есть автосохранение в файл.

**Автосохранение в файл.** Кнопка в боковой панели, блок «Данные»: один раз выбираете файл на диске,
и приложение пишет туда состояние при каждом изменении — без сервера и без авторизации.
Положите файл в синхронизируемую папку (iCloud, Яндекс.Диск, Dropbox) — получите доступ
с других машин и защиту от чистки кеша.

- Ссылка на файл переживает перезагрузку (хранится в IndexedDB). Браузер может попросить
  подтвердить доступ заново — кнопка станет янтарной «Разрешить доступ к файлу»,
  разрешение запрашивается одним кликом.
- Если в выбранном файле уже есть данные, приложение спросит: загрузить их или перезаписать
  файл текущими. Молча перетереть нельзя ни в одну сторону.
- Запись отложена на полсекунды, чтобы не дёргать диск на каждом переключении фильтра.
- Нужен File System Access API — есть в Chrome и Edge. В Firefox и Safari кнопки не будет,
  там остаётся экспорт и импорт JSON.

**Экспорт и импорт JSON** — рядом, в том же блоке: ручной бэкап и перенос между браузерами. Чужой json
приложение не примет: если в файле нет массива инцидентов, состояние не тронуто.

## Тесты

```bash
npm test
```

57 юнит-тестов на `node:test`, без зависимостей (Node 18+). Покрыты разбор дат и границы
периодов, нормализация модели, фильтр ранга во всех режимах, метрики, фильтры таблицы,
разбор CSV и бэкап — то есть всё, где ошибка не видна глазом и тихо портит цифры на митинге.
DOM-слой (`ui.js`, `app.js`) тестами не покрыт: там нет логики, только отрисовка.

## Структура

```
index.html      каркас интерфейса и модалки
css/styles.css  дизайн-система: токены, компоненты, тёмная и светлая темы
js/store.js     модель инцидента, настройки, периоды, localStorage
js/sheets.js    XLSX и XLS → CSV через SheetJS (js/vendor, грузится лениво)
js/csv.js       разбор выгрузки Jira и раскладка колонок
js/metrics.js   все формулы — чистые функции
js/charts.js    SVG-графики без библиотек
js/filesync.js  автосохранение в файл через File System Access API
js/ui.js        рендер интерфейса
js/app.js       состояние экрана, события, импорт, экспорт
sample/         демо-выгрузки: incidents.csv и jira-ru.xlsx с русскими заголовками
tests/          юнит-тесты, tests/helpers/load.js — загрузчик
```
